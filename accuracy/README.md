# 精度回帰テスト

AI が Novi UI を**正しく書けるか**を測る。主観で判断せず、機械的な2つだけで合否を決める。

- `tsc --noEmit` の型エラーが 0 件
- Raster の禁止クラスが 0 件

文章の一致は見ない。LLM は非決定的なので、表現の揺れを不合格にすると検査が安定せず、
やがて誰も見なくなる。

## CI では回さない（ADR-A5）

生成には LLM 呼び出しが要る。CI で毎回回すと従量課金になり、運用費 0 円の前提が崩れる。
**リリース前**と **`llms` の生成ロジックを変えたとき**に、手元の AI 環境から実行する。

このスクリプト自身は LLM を呼ばない。生成は人が AI にやらせ、その出力をファイルで受け取る。

## 手順

1. ビルドして生成物を最新にする

   ```bash
   pnpm build
   ```

2. `apps/docs/public/llms-full.txt` を AI の文脈に与える。
   **リポジトリのコードは見せない。** 利用者と同じ条件にする。

3. `prompts.json` の指示文を1つずつ渡し、TSX を書かせる。

   AI への依頼文の例:

   > 次のドキュメントだけを参照して、React のコンポーネントを1つ書いてください。
   > 説明は不要で、コードだけを返してください。
   > 指示: 「保存と取消のボタンを横に並べてください。保存の方を目立たせ、保存中は押せないようにしてください。」

4. 出力を `accuracy/generated/<id>.tsx` として保存する。`<id>` は `prompts.json` の `id`。

5. 実行する

   ```bash
   pnpm accuracy
   ```

`generated/` は git 管理外。生成物は毎回捨ててよい。**残すのは結果だけ。**

## 不合格だったとき

**生成物を直さない。** 個別のコードを直しても、次に生成したときに同じ間違いが再現する。

直すのは `llms.txt` の側。

1. 何を間違えたかを分類する（例: `onClick` を使った / `shadow-sm` を書いた / Provider で包んだ）
2. その規約が `llms.txt` の冒頭「必ず守ること」に**書かれているか**を確認する
   - 書かれていない → 追加する
   - 書かれている → 位置が後ろすぎるか、表現が弱い。前に出すか、間違いの例を添える
3. 規約は [`generate-llms-txt.mjs`](../apps/docs/scripts/generate-llms-txt.mjs) の `CONVENTIONS` にある
4. `pnpm build` して、その指示文だけ再生成し直す

**テストが文書を改善するループ**になっている。ここで足した1行が、以後すべての利用者に効く。

## 指示文を足すとき

コンポーネントを追加したら、`prompts.json` にも指示文を足す。
足し忘れると `pnpm accuracy` が「指示文の無い実装済みコンポーネント」として落ちる。

指示文には **API 名を出さない**。「`Button` を使って」と書くと、
思い出す力ではなく写す力を測ることになり、試験の意味が無くなる。
