# Novi UI

> One core, several aesthetics. It survives being written by an AI.

A React component library built on React Aria Components.
`@novi-ui/core` owns behaviour, accessibility and the type contracts; theme packages own
**structure and style only**. Switching themes changes more than colours and corner radii —
it changes how the DOM is assembled.

> **Early development.** The API will change.

## Packages

| Package | Role |
|---|---|
| [`@novi-ui/core`](https://www.npmjs.com/package/@novi-ui/core) | Behaviour, a11y, type contracts, token conventions. **Ships no styles at all** |
| [`@novi-ui/raster`](https://www.npmjs.com/package/@novi-ui/raster) | Theme 1: minimal / Swiss. Hierarchy from rules and whitespace |
| [`@novi-ui/tactile`](https://www.npmjs.com/package/@novi-ui/tactile) | Theme 2: touch-first. Surfaces lift; Modal becomes a bottom sheet |
| [`@novi-ui/flatlay`](https://www.npmjs.com/package/@novi-ui/flatlay) | Theme 3: no z-axis. Nothing floats; Modal becomes a full-page takeover |
| [`@novi-ui/mcp`](https://www.npmjs.com/package/@novi-ui/mcp) | MCP server for AI agents. Read-only and offline |

All three themes implement **23 components (25 contracts)** and expose an identical public API.

## Getting started

**Requires React 19 and Tailwind CSS v4.** A theme's CSS ships token definitions only;
the component classes are generated by *your* Tailwind. Without Tailwind, nothing renders.

```bash
pnpm add @novi-ui/core @novi-ui/raster react-aria-components
```

```css
/* app/globals.css */
@import "tailwindcss";
@import "@novi-ui/core/base.css";
@import "@novi-ui/raster/raster.css";

/* let Tailwind see the classes the theme emits — path is relative to this CSS file */
@source "../node_modules/@novi-ui/raster/dist";
```

```tsx
import { Button, Input } from '@novi-ui/raster'

export function SignInForm() {
  return (
    <form>
      <Input label="Email" type="email" isRequired />
      <Button type="submit" color="primary">Send</Button>
    </form>
  )
}
```

No provider is required. Theme, colour scheme and colourway are attributes on `<html>`.

```html
<html data-novi-theme="raster" data-novi-scheme="dark" data-novi-color="brick">
```

Prop names follow the React Aria conventions: `isDisabled` rather than `disabled`,
`onPress` rather than `onClick`.

## Why split core and themes

We want a real difference in aesthetics between themes — which means a difference in DOM
structure. We also want one documentation site, an identical public API across every theme,
and accessibility fixes applied in exactly one place.

To satisfy all three, **core decides the *names* of the parts (slots) and never the JSX**.

```ts
// core decides names and types, nothing else
export const modalSlots = ['backdrop', 'panel', 'header', 'title', 'closeButton', 'body', 'footer'] as const
export const modalRequiredSlots = ['backdrop', 'panel', 'body'] as const
```

A theme is free to choose order, nesting and element types as long as it renders the required
slots. A theme that puts the close button at the top right, one that puts it full-width in the
footer, and one that does not float at all and becomes the page itself can coexist behind
**the same props and the same slot names**.

Every theme emits `data-slot="<name>"`. That single convention makes tests, visual regression,
user CSS overrides and an AI's understanding of the structure work across all themes.
