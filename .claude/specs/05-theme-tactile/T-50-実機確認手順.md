### B-5. 日本語入力（IME）

https://novi-42r.pages.dev/ime-probe/

**このページの目的**: 変換確定の Enter が `onKeyDown` に届くと、利用側の「Enter で送信」が暴発します。届いた回数が画面に出ます。

1. 上の Input をタップ
2. Gboard で `にほんご` と入力（**変換候補が出ている状態**にする）
3. 変換を確定する（Enter / 確定キー）
4. [ ] **「ハンドラに届いた Enter」が `0` のまま**であること
5. そのまま何も変換していない状態で Enter を押す
6. [ ] 今度は `1` に増えること（抑制しすぎて普通の Enter まで殺していないか）

TextArea でも同じことを確認してください（`かいぎょう` で変換確定 → 0 のまま）。

> **記録してほしいこと**: 4 が `0` でなかった場合、そのときの Gboard の設定（予測変換の有無・確定キーの種類）を控えてください。Android の IME はベンダー差が大きく、再現条件が分からないと直せません。

## 参考: iOS 側で分かったこと（実施済み分）

| 項目 | 結果 |
|---|---|
| safe-area | **iOS Safari のブラウザモードでは上下左右すべて 0**。アドレスバーを縮めた後も 0。34px が入るのは standalone（ホーム画面に追加）や Android の一部だけ |
| dvh | アドレスバー表示時 714 / 縮小時 754 と正しく追随（`svh=714` `lvh=754` 固定） |
| 入力ズーム | フォーカスしても `visualViewport.scale=1`。入力欄は 17px |
| ボトムシート | `bottom` が `innerHeight` と一致（下端に張り付き）、最大高は 60dvh |
| Select シート | `position:fixed` / 全幅 / 下端固定。ADR-T2 の `!important` 上書きが実機でも効いている |

> docs には Web App Manifest が無いため、**iOS で standalone にはできません**。
> safe-area 34px の環境を実機で見たい場合は manifest の追加が要ります（現状は
> `safe-area.spec.ts` が CDP で inset を注入して検査しています）。
