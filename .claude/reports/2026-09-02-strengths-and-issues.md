## 総評

工学は世界水準、露出と導線が未着手。一言で「反物は一級品だが、店の看板とタグが無く、入口の説明が実物と食い違っている」状態。

2026 年の市場変化が1つある。shadcn/ui が 8 つの「スタイル」を出し、7月には React Aria をベースとして選べるようにした。「react-aria + Tailwind の1コアに複数の見た目」はもう Novi 固有の売りではない。Novi に残る唯一性は **「見た目ではなく DOM 構造まで変わる」**（Flatlay の全画面テイクオーバー、z 軸なし、フロー内展開）と **日本語 IME 安全性**、そして **アパレル由来の色の物語** の3つ。この3つがいま、サイトのファーストビューに出ていない。

## 伸ばすべき強み

### 1. 構造が変わるモデル（他に無い）
shadcn の 8 スタイルは「ジオメトリと余白と手触り」までで、Modal が全画面になるような構造差は無い。Novi は slot 契約で構造差を保証し、3本の一致率が 49〜55% まで割れている（ADR-09）。
- 現状の見せ方: ホームの三連は Card 1枚。「角丸と余白が違う」以上に見えない
- 伸ばし方: **Modal / Select / Toast を3モデルで開いた状態で並べる**。Raster は浮く、Tactile はシート、Flatlay はテイクオーバー。これが最初の1画面

### 2. 検査文化（証明物の中身）
テスト 1,200 件超、TODO ゼロ、design rule を CI で強制、48 判定のコントラスト検査、slot 契約テスト、core の RSC 安全性を dist で検査、IME の isComposing 検査。「AI に書かせても崩れない」の裏付けが全部ある。
- 現状: 裏付けが外から見えない
- 伸ばし方: コンポーネントページに「この組合せは検査済み」を可視化する。設計思想ページ（Why Novi）を1本書く

### 3. 色の物語 + アパレル知見
Print Inks / Textile Dyes / Stationery の命名と、トーン=モデル・色=カラーウェイの構造。Lookbook が最良ページ。競合の命名（shadcn は星名）と重複なし。
- 現状: Lookbook は染料（色見本）を見せるが、服（コンポーネント）に着せていない
- 伸ばし方: 各色の下に同じ Card / Button を着せて並べる。「決めごと」に Flatlay（ダブルエントリー）を追記

### 4. 日本語 IME 安全性
変換確定 Enter の誤送信防止を実機検証済み。国内向けの本物の差別化。ホームに一文しかない。

### 5. 土台の軽さ
Provider 不要、core は React を import しない RSC 安全設計、テーマ CSS は gzip 1.7〜3.0KB。

## 課題（優先順）

### P0 信頼を毀損しているもの（各1時間以内）
| 課題 | 事実 |
|---|---|
| LICENSE ファイルが無い | package.json は MIT 宣言、GitHub の licenseInfo は null。企業は採用判断できない |
| favicon 404 / OGP 無し | 8/23 診断の P0 が本番で未解決。共有時にカードが出ない |
| ルート README が古い | tactile / flatlay がパッケージ表に無い。「20 コンポーネント」も 24 が正 |
| npm の readme が空 | core / raster とも npm ページで白紙 |
| MCP の鮮度ズレ | mcp 0.1.2 は core 0.4.0 の余白トークン規則を含まない。AI が古い規約で書く |
| STATUS.md が 10 日陳腐化 | flatlay と design-voice が未記載、版数が古い |

### P1 導入の壁
1. **Tailwind v4 が隠れた必須依存**。テーマ CSS はトークンのみで、クラス文字列は JS 側。利用者の Tailwind が `@source` で拾わないと完全に無スタイル。「CSS を2行 import すれば動く」は不正確で、AI が `@source` を書き忘れる経路でもある。
   選択肢: (a) 正直に書いて peer 宣言と手順を足す（即日）、(b) プリコンパイル CSS を同梱して Tailwind 不要にする（ゼロ設定になり、AI の書き忘れ経路も消える）。推奨は (a) を今日、(b) を検討。
2. **はじめにページに theme / scheme / color 切替が無い**。Raster しか登場せず、他2モデルの存在が導入ページから分からない。ダーク切替のスニペットもどこにも無い。
3. **業務画面の部品が無い**。Combobox / DatePicker / Table / Pagination / NumberField / Slider が全滅（19 項目中 3 のみ）。目的1「実務資産」と直接矛盾。RAC は全部持っているので構造コストは低く、在庫・受注のようなアパレル業務に直結する。
4. **docs の深さ**。各コンポーネントの例が1つ、Do/Don't が1文、a11y は定型3箇条の使い回し。レシピ（ログイン / 設定 / 一覧）が無く、ダッシュボードデモはコード非公開。
5. **表記の食い違い**。「組み上げるとこうなります」は Raster 前提の本文だが既定表示は Tactile。ヘッダは「テーマ」、本文は「モデル」。

### P2 発見と市場
- **日本語のみ**。サイト・README・llms.txt・MCP 応答すべて。英語圏の開発者と英語プロンプトの AI を排除している。日本発ソロ OSS が伸びた事例は英語露出が前提。
- **AI 配布の標準が変わった**。2026 年は MCP 単体でなく、SKILL.md + shadcn レジストリ互換 + llms.txt の3点セットが標準。Novi は MCP と llms.txt のみ。llms.txt 自体に採用を促す証拠は見つからない。
- **シグナルはゼロ**。star 0、issue 0、Web 言及なし。npm 週 140〜410 DL はミラー由来と見るのが妥当。
- **ホームが用語先行**。core / slot 契約 / 支配軸 が説明なしで登場。「何・誰向け・入れ方」とGitHub / npm 導線が無い。

## 進め方の提案

**今週（露出の穴を塞ぐ）**: P0 の6件 + Tailwind 必須の明記 + はじめにページの3属性追記。設計判断は要らない。

**次の2週（唯一性を前面に）**: ホーム最上段を「Modal を3モデルで開く」に差し替え。Lookbook に着せる。Why Novi ページ。英語版は README / getting-started / llms.txt の3本だけ先に。

**その後（実務資産と AI 配布）**: Table / ComboBox / DatePicker / NumberField / Pagination を契約に追加。利用者向け SKILL.md と shadcn 互換レジストリ。MCP の鮮度を changeset に連動。

**判断が要るもの**: プリコンパイル CSS 同梱（Tailwind 非依存化）、8色固定の維持、未使用 slot（arrow / Toast.icon）の削除。
